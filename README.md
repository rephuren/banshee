# banshee

Движок правил для защиты на Rust: читает правила Sigma и YARA, прогоняет их по журналам событий и по файлам и сводит срабатывания по тактикам и техникам MITRE ATT&CK.

Работайте только с журналами и файлами, которые вы вправе анализировать.

## Статус

Готов движок Sigma. YARA в работе (см. [CHANGELOG](CHANGELOG.md)).

## Быстрый старт

```bash
cargo build --release
target/release/banshee sigma --rules rules/sigma --events examples/events.jsonl
target/release/banshee sigma --rules rules/sigma --events examples/events.jsonl --json --min-level high
cargo test
```

Код возврата: `0` срабатываний нет, `1` есть срабатывания, `2` ошибка (неверные аргументы, нет файла).

События читаются из JSON Lines (по объекту на строке) или из одного JSON-массива. Строки, которые не являются JSON-объектами, не пропадают молча: их число и первый номер выводятся.

## Что понимает Sigma-часть

- Выборки по полям (карта это И, список карт это ИЛИ), вложенные поля (`process.name`) и плоские ключи с точками.
- Модификаторы: `contains`, `startswith`, `endswith`, `all`, `re`. Подстановки `*` и `?` с экранированием `\`. Сравнение строк без учёта регистра. Значения `null`, числа, логические.
- Выборки-ключевые слова (список строк без полей): ищутся по всем строкам события.
- Условия: `and`, `or`, `not`, скобки, `1 of sel_*`, `all of them`, список условий (любое из).
- Теги `attack.t1059.001` и `attack.execution` попадают в сводку техник и тактик.

**Всё остальное отклоняется явно, с причиной, а не игнорируется:** агрегации (`count`, `near`, `timeframe`), правила корреляции, коллекции `action: global`, модификаторы `base64`, `base64offset`, `windash`, `cidr`, `utf16`, `exists`, `gt`/`lt`. Файл такого правила попадает в список пропущенных вместе с причиной.

В `rules/sigma` лежат четыре моих правила в учебных целях (PowerShell с закодированной командой, «curl в sh», изменение `authorized_keys`, новая задача cron). Это не копии правил SigmaHQ.

## Как проверялось

- Тесты на каждый элемент подмножества: подстановки, модификаторы, условия, `null`, регулярные выражения, ключевые слова, вложенные поля, 11 вариантов заведомо неверных или неподдерживаемых правил.
- Интеграционный тест запускает настоящий бинарник на четырёх правилах и восьми событиях и проверяет, что срабатывают ровно четыре подготовленных события, а безобидные (`cmd /c dir`, обычный `curl`, `sshd`, `dpkg`) молчат.
- CI: `cargo fmt --check`, `clippy -D warnings`, `cargo test`.

## Ограничения

- Это подмножество Sigma, не полная реализация и не замена `sigma-cli` или `chainsaw`. Реальные правила из SigmaHQ часто используют неподдерживаемые модификаторы и будут пропущены, а не неверно истолкованы.
- Нет сопоставления полей по `logsource` и конвейеров преобразования полей (field mapping): правило и событие должны называть поля одинаково.
- Нет встроенной матрицы ATT&CK: техники берутся из тегов правила как есть и не проверяются по настоящей матрице.
- Проверялось на моих правилах и придуманных событиях; на реальных журналах Windows или Linux не прогонялось.
